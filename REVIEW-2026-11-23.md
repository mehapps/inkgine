# Pre-window review 2026-11-23 (read-only, CPU only)

Scope: engine.py, server.py, spec_runner.py, spec.py, dspark.py, decode_batch.py (step/commit/tap history), kvpool.py,
grammar.py, read against NOTES.md (11-22/23 log) and ARCHITECTURE.md. No repo file was changed. The repro scripts are
in /tmp/review_repro/ (run with `engine/.venv/bin/python`, stubs only, a few seconds each).

Ranked by severity, then likelihood. Confidence: H / M / L.

## Summary
Three findings are in the same class as the two the GPU caught. Each one breaks real serving and none is covered by a
CPU test:
1. `Engine._spec` can drop the drafter it has just loaded, which makes the request fail with a 500. While VRAM stays
   tight, every spec request fails the same way.
2. With the shortlist head on, a drafter State that gets reused or reset raises KeyError. The usual result is that
   spec turns off without a message. Sometimes the whole decode batch gets a 500.
3. `INK_SPEC_GATE` picks the verify width from later rows' confidences. That biases sampled output.

All three are reproduced. Flags 2 and 3 are on in window_spec3 configs A, B and C. Finding 1 gets much more likely in
configs B and C (+0.9 GB embed table, FP8 decode copy). After those come a cache-file loss under OOM, the blast radius
of decode-step exceptions, and some VRAM and SSD waste.

## 1. `_spec` drops the just-loaded drafter, then crashes. CRASH (500), conf H, REPRODUCED
`engine.py:369-382` (with `free_vram` 327-340 and `drop_drafter` 342-349)
- Code: `if self.ds is None: free_vram(...); self.ds = DSpark(...); ds.live = 0`, then with no idle State
  `free_vram(MARGIN//2 + DS_ST_MB)`. When that is short it calls `drop_drafter()` (keep=0), which sets `self.ds = None`
  because `live == 0`. Next comes `Spec(None, ...)`, which builds fine, and then `self.ds.live += 1` raises
  AttributeError. `_spec` only catches `OutOfMemoryError`, so the error goes up through `start()` to
  `Scheduler._start` and `_fail`, and the request gets a 500. Pages are released, so nothing leaks.
- Scenario: the drafter is not loaded. It gets dropped whenever any `free_vram` runs with no spec request live, for
  example a prefill chunk under pressure, solo mode or an OOM. Then a spec request starts. The first `free_vram` unparks
  until about 1.8 GB is free, loading the drafter takes about 0.8 GB, the second ask (about 1.18 GB) is short, the
  drafter is dropped, and the request crashes. The next spec request reloads the weights and crashes again. So while
  free VRAM sits in that band, every default request fails. A second path needs no fresh load: `ds` loaded, `live == 0`
  and `ds_free` empty, which happens after `_spec_fail` of the last spec request.
- Likely in window_spec3 B (EMBED_GPU +0.9 GB) and C (FP8 decode copy). Possible near 1M or during the 16.7 MP gate
  image. Earlier worst free values were 1281 MiB (gate image) and 1.34 GB (1M needle).
- Repro: `/tmp/review_repro/r1_spec_ds_none.py` (fake DSpark, `mem_free` = 1 GiB) prints
  `AttributeError 'NoneType' object has no attribute 'live' | ds after: None`.
- Fix: in `_spec`, reserve before the second `free_vram` (`self.ds.live += 1` before it, undo it on failure), or have
  `drop_drafter` called from inside `_spec` never drop the weights. Also make `_spec` catch any Exception and return
  None (spec off) instead of letting it become a 500.

## 2. Shortlist head: `DSpark.reset` leaves `st.dslot` stale, so the next `note()` raises KeyError. SPEC OFF / BATCH 500, conf H, REPRODUCED
`dspark.py:160-169` (reset) and `383-399` (note); callers `spec_runner.py:93-95, 123-125, 130-131, 153-157, 258-259`
- `reset()` clears `st.dmap` and `st.dptr` but not `st.dslot`. The first new dynamic token after a reset lands in slot 0,
  where `dslot[0]` still holds the old token, so `del st.dmap[old]` raises KeyError.
- Every State reuse goes through `reset`: a State from `ds_free` (every spec request after the first), dormant wake
  (`propose` after SLEEP+WAKE), `attach`/`prompt` gap resets, and `warm_drafter`'s State once a request has used it.
  This only happens with the shortlist on: `INK_DSPARK_SHORT`, or `INK_FP8_DECODE=1` (unembed8 forces the shortlist).
- Outcome: if the prompt or history holds a non-static token, `note(hist())` in `propose` raises, the error is caught,
  and `_spec_fail` turns spec off for the request with only a log line. The State is discarded, so the next request
  allocates a new one and captures its graphs lazily mid-serving. If the history is all static (short plain-English
  chats) and the first rare token comes out of a drafting round, `settle` raises from `note(out)`. `settle` is not
  guarded (`engine.py:584`), so `Scheduler._decode` fails **every request in the batch** with a 500.
- In the window this shows up as falling spec speedups and "spec off for a request: drafter failed: KeyError" lines.
  test_dspark checks only `dmap` and `md` after reset (`tests/test_dspark.py:287-288`).
- Repro: `/tmp/review_repro/r2_note_reset.py` prints `note() after reset raised KeyError 10`.
- Fix: in `reset`, also `st.dslot = [-1] * self.dyn` when the State has one. Add a test that runs two sequences on one
  State with the shortlist on.

## 3. `INK_SPEC_GATE`: verify width depends on the drafted tokens themselves. WRONG OUTPUT DISTRIBUTION (sampled), conf H, REPRODUCED
`spec.py:141-154` (`Gate.pick`), `spec_runner.py:193-196`
- `pick` takes the argmax over m in {1, 3, 7} of expected tokens from conf[0..m-1]. conf[j] depends on drafts
  d_1..d_j. Choosing m=3 over m=1 uses conf[2], which depends on d_2, so whether d_2 gets verified depends on d_2's own
  value. Exact speculative sampling needs a stopping rule: including d_{j+1} may depend only on conf[0..j]. The notes'
  claim ("conf_i is a function of q_i only") holds row by row but not for this global argmax. The chi2 test
  (`test_spec.py:113-115`) only uses a 2-draft rule that is a valid stopping rule.
- Repro: `/tmp/review_repro/r3_gate_bias.py` uses the real Gate.pick and accept. In the toy, conf[2] is high only when
  d_2 = 0. It gives P(token 2 = 0 | token 1 accepted) = 0.901, where the exact value is 0.800. The real bias depends
  on how drafter confidence correlates with the drafted token. It is not zero, and greedy is unaffected.
- Fix: make the width choice sequential. Going from width w to the next width may use only conf[0..w] (unknown later
  rows at their prior). Or use the Gate for greedy only and Width for temperature > 0.

## 4. `kvpool._read` deletes good cache files on CUDA OOM. CACHE LOSS, conf H, REPRODUCED
`kvpool.py:118-130`
- The `except (..., RuntimeError)` branch also catches `torch.OutOfMemoryError` (a RuntimeError subclass) from
  `.to(dev)`. A disk state (~200 MB to the GPU) or page read under VRAM pressure deletes the file and returns None, so
  the request cold-prefills. Restores happen exactly when VRAM is tight (long chats), so the most valuable files go
  first. Other transient CUDA errors are treated the same way.
- Repro: `/tmp/review_repro/r4_read_oom_deletes.py` prints `read -> None | file still there: False`.
- Fix: read and checksum on the host first and treat only parse/checksum errors as corruption. Let OOM propagate (start()
  already handles it) or return None without deleting.

## 5. Any exception inside `decode_step` fails the whole batch; `settle` is unguarded. CRASH BLAST RADIUS, conf H (design)
`engine.py:574-589`, `server.py:252-258`
- `propose` failures are contained (`_spec_fail`), but `settle` (note, accept/accept_dev, the grammar
  `RuntimeError('grammar rejected token')`, commit), `_process_rows`, the logprob code and `_take` are not. One bad
  request 500s every co-batched request. Finding 2 is a live example.
- Fix: wrap each spec request's post-step block (process, settle, feed) in try/except. On error, commit that slot's
  pending rows (`bd.commit({slot: 1})`) or free it, then fail only that request (mark it and let the scheduler `_end` it
  with an error). `OutOfMemory` can stay batch-wide.

## 6. Disk write errors propagate out of page eviction and unparking. 500s, possibly repeated, conf M, not reproduced
`kvpool.py:84-96` (`_write`), `262-267` (`_evict`), `432-439`; `engine.py:318-322`
- `_write` raises OSError (ENOSPC from a race with HiCache or renders, EIO). Callers are `_evict` inside `_alloc` (so
  `reserve`/`fork`/`_load_page`, i.e. admission and prefill) and `unpark` inside `park`/`free_vram`/`admit`. Nothing
  catches it, so the request fails. The node stays and the next request that needs eviction hits the same spill, so
  500s keep coming while the disk keeps failing. The parked entry popped before the failing `unpark` is lost; its pages
  only come back through `Table.__del__`.
- Fix: catch OSError in `_save` (remove the tmp file, log, return False). A spill that fails just drops the page.

## 7. Non-streaming requests keep generating after the client disconnects. PERF/CAPACITY, conf M-H
`server.py:487-494`
- Only the streaming path is cancelled by Starlette. For `stream: false` nothing sets `cancel` on disconnect, so the
  request runs to max_tokens (default 4096) and holds a slot and pages. LiteLLM timeouts plus retries stack duplicates
  this way.
- Fix: poll `await request.is_disconnected()` (for example a small task that sets `cancel`) in the non-stream branch.

## 8. `free_vram` drops drafter weights and States before parked prompts. PERF (reload plus lazy graph captures in serving), conf H
`engine.py:335-340`
- Under pressure the order is: empty_cache, then `bd.drop()` plus `drop_drafter()` (weights too if `live == 0`), and
  only then LRU parked states. Every prefill chunk calls `free_vram(MARGIN)`, so a tight-VRAM long prefill throws away
  the drafter and its warmed graphs. The next spec request reloads (1-2 s) and captures up to 14 graphs inside timed
  decode. This matches the g2 "spec slower" note. It is also the path into finding 1.
- Fix: unpark parked states before dropping the drafter, or drop only idle States and keep the weights unless the ask
  still fails after unparking.

## 9. Cancelled or abandoned preempted requests leave parked entries that later go to disk. VRAM/SSD WASTE, conf H
`engine.py:522-526, 724-737`, `server.py:140-143, 199-210`
- `preempt_decode` parks with keep=True, and `preempt_prefill` with keep=a >= DISK_MIN. If the client then disconnects
  while the request waits in the heap, `_admit` drops it from the heap but its parked entry stays. That costs about 200
  MB of GPU and one of only INK_PARK=2 slots, pushing out useful prompts. When the LRU evicts it, the state is written
  to disk (keep). `_preempt` also doesn't check `cancel` before parking.
- Fix: when dropping a cancelled request from the heap, unpark its entry (disk=False, matched by keys). Check `cancel`
  in `_preempt`.

## 10. n > 1 with spec: choices 2..n draft with no context; a disk-restored choice 0 isn't re-parked. PERF, conf H
`engine.py:445, 516-517`
- Choices 2..n restore the whole prompt (P = len), so `Spec(start=P)` has no prompt taps and acceptance starts near
  zero. Width may switch drafting off, and SLEEP sends the choice dormant. Separately, if choice 0 itself restored its
  full prompt from disk (P == len), nothing is parked on the GPU, so every other choice re-reads the ~200 MB state from
  disk.
- Fix (cheap): park after a full disk restore when n > 1. Optional: keep choice 0's prompt taps, or at least the
  shortlist note, for the siblings.

## 11. CUDA tensors are created on the executor thread while the scheduler may be capturing a graph. RARE 500 / spec off, conf L-M
`engine.py:194-195` (logit_bias tensors in `Request.__init__`), `181-182` (CUDA Generator), `server.py:450-453`
- `build()` runs in the default executor. `torch.tensor(..., device=cuda)` makes a pageable H2D copy on the legacy
  stream. If the scheduler thread is capturing at that moment (lazy drafter graphs, a new BatchDecoder R bucket, or
  after `bd.drop()`), capture in the default "global" mode can be invalidated, or this call errors. logit_bias is rare
  in traffic.
- Fix: keep `bias` on the host in `Request` and move it to the device lazily on the scheduler thread, in `_process`.

## 12. Smaller items (low)
- `server.py:414`: max_tokens <= 0 is accepted (`or 4096` only catches 0/None). A negative value makes `need` smaller
  than the prompt, so prefill grows the table on the fly, and an assert fires if the pool is full. An out-of-range
  `seed` raises RuntimeError in `build()`, which becomes an unhandled 500. Validate `max_tokens >= 1` and the seed range.
- `engine.py:422-424` with `server.py:157-173`: `can_start` is True whenever anything is parked, so a page-blocked
  head runs `restore()` every 1 s retry. That can mean a disk state read (~200 MB) plus page loads that evict cached
  pages, then NoRoom. The fix is a cheap pages-only check before restore.
- `engine.py:518-519`: a prompt resumed after a preempted prefill reports its own parked progress as
  `cached_tokens` (usage over-reports cache hits).
- `engine.py:736` / `kvpool.publish`: a parked decode publishes its generated-token pages into the prefix tree, so a
  later prompt with the same tokens would get decode-computed KV (bf16-noise-level difference). Only worth knowing.

## Checked and consistent (no finding)
- json cut fix: `settle` cuts at `cons.done`; `_feed(last=)` honours it only at the last token; stop ids cut first.
  Every place that truncates `out` (EOS, END with thinking off, cons.done) also sets `r.done`, so `preempt_decode`'s
  `len(ids) == pos` assert can't trip after a cut round.
- Rows: `spare = 16 - len(reqs)` and per-request `kcap` keep the step at <= 16 rows. Pad rows: live 0, taps go to the
  trash slot. `tok={r0+1: dtok}` offsets match the rows built in the dev_tok branch, and `step` skips host tokens for
  those rows.
- Catch-up: after a drafting round `st.n == pos`. The next round stages `tap_hist(pos_old, a+1)`. A k=0 round catches
  up one 8-block at lag >= 8, so lag stays <= 8, well under the TH-8 = 24 assert. Rejected verify rows only write tap,
  ring and page positions > the committed pos.
- Grammar-rejected draft ("bad"): it gets no verify row and p = 0, so `accept` and `accept_dev` can never accept it,
  and `accept_dev`'s missing bonus row is unreachable. The masks along the draft path give correct per-row logprobs.
  ToolCall rollback across name -> json (fresh matcher, immutable state) is sound.
- max_tokens: drafts <= left-1, so emitted <= left. The verify positions stay below `need`, so no page outside the
  reservation is written.
- Pages: fork, publish, restore, match refcounts hold. Matched pages carry +1, so a later `_load_page` eviction can't
  take them. Parked and restored tables never write into shared full pages (writes go to positions >= P, a private
  partial page or new pages).
- DSpark graph pool (WeakSet): the pool changes only when no State holds any graph, so every live graph is always in
  the current pool. The window-g failure mode is closed. All graph outputs go into buffers allocated outside the pool,
  so sharing it across States is safe regardless of replay order.
- ds.live accounting: `_spec` +1, `_end_spec`/`_spec_fail` -1, lookup excluded. `ds_free` is emptied before `ds` is
  dropped. The one exception is finding 1.

## Test gaps (no CPU test covers these)
1. `Engine._spec` under VRAM pressure (`mem_free` small) with the drafter unloaded and/or an empty `ds_free` (finding
   1). test_dspark uses `mem_free = 1 << 62`.
2. Shortlist State reuse: two sequences on one State, dormant wake, attach/prompt-gap reset, each followed by `note`
   of new tokens (finding 2).
3. Gate exactness with >= 3 drafts and m chosen from {1, 3, 7} by `pick` itself, with conf that depends on the drafts
   (finding 3). The current test uses a valid 2-draft stopping rule.
4. Exception injection in `settle`, `_process_rows` and `_take` with several requests in the batch: only `propose` and
   prompt failures are injected (test_api 2c). Check the other requests survive and `bd.pend` is clean.
5. kvpool `_read` hitting OOM or other CUDA errors, and `_write` hitting OSError (ENOSPC) during eviction and unparking.
6. A real BatchDecoder mixed step: two spec slots + plain rows + dev_tok in one step, the 16-row cap with 4 slots at k=7,
   and commit of two verify slots in one step. CPU uses SeqBatch, which doesn't enforce the tap-history lag limit
   (TH-8) or pinned-buffer reuse.
7. n > 1 with spec on: a cancel mid-stream, a choice erroring, choice 0 restored from disk, prompts >= SNAP_MIN (parked)
   vs below it.
8. Non-streaming client disconnect (finding 7) and a cancelled request waiting in the heap after preemption (finding 9).
9. Lazy graph capture (drafter or new R bucket) happening while the HTTP thread builds a request with logit_bias
   (finding 11). This can only be checked on a GPU.
10. Flags-on `test_engine_cpu` (SHORT/CTXB/GATE/ACCEPT_DEV/EMBED_GPU) is still listed as not run in NOTES; it would
    have hit finding 2 through State reuse.
